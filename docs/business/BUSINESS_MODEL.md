# Modelo de negocio recomendado

## 1. Tesis

El dato normativo es público. El valor no está en revender un PDF, sino en convertir reglas académicas heterogéneas en una capa operacional:

**currículo verificado + procedencia + auditoría + oferta + planificación + optimización + gobernanza.**

## 2. Estrategia de producto

### Student-first
La experiencia individual crea adopción, datos de uso y validación de necesidades:
- malla;
- auditoría;
- planner;
- explicación;
- alertas.

### Institutional
La capa institucional concentra mayor disposición a pagar:
- backoffice normativo;
- revisión/publicación;
- cohort audit;
- asesoría académica;
- impacto de reformas;
- demanda potencial;
- analítica agregada;
- integrations/SSO;
- SLA/soporte.

## 3. Líneas de ingreso posibles

### B2C
Opción, no decisión definitiva:
- core de comprensión/auditoría gratis;
- premium por planificación avanzada, múltiples escenarios, optimización, alertas y exportes.

Ventaja: adquisición orgánica.
Riesgo: cobrar por una necesidad académica básica puede limitar adopción.

### B2B SaaS
Cobro por:
- institución/programa;
- usuarios administrativos;
- estudiantes activos;
- módulos avanzados.

### Servicios
- digitalización/versionado de planes;
- integración;
- migración;
- capacitación;
- soporte;
- análisis curricular.

## 4. Recomendación

No implementar billing duro hasta decidir marca/mercado, pero diseñar:
- Organization;
- entitlement/capability layer;
- plan features;
- usage metering opcional.

Nunca dispersar `if premium` por UI. Las capacidades se resuelven centralmente.

## 5. Moat

- corpus curricular estructurado y versionado;
- motor genérico de reglas;
- trazabilidad normativa;
- histórico de cambios;
- UX explicable;
- integraciones institucionales;
- dataset de golden audits;
- confianza operacional.
